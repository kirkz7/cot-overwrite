Last Word Wins?

When a reasoning trace or a context states several values for the same quantity (overwritten states, self-corrections, competing conclusions), which one does a language model believe? This report summarizes the latest results of 22 experiments, the scope of the findings, and the decisions to discuss next.

Summary

When a language model reads text that states several values for the same quantity, it defaults to the value presented last. For text written in chronological order, including the model's own reasoning, this default is usually right. When the text is not presented in chronological order, the default overrides explicit temporal markers (step numbers, “listed from most recent”), and an explicit retraction (“Wait, that's wrong.”) only partly offsets it. Qwen3-14B can use well-structured step numbers; OLMo-2-13B, at the same scale, still reads mostly by position.

Where this stands: evidence across two model families and 1.7B–14B supports a paper on position-based reading of state. Whether it is main-conference material depends on two things: whether the effect persists at 32B and 70B, and whether it reproduces in natural non-chronological settings such as agent memory retrieval, newest-first logs and multi-source contexts.

Evidence 1

When order matters: only when states are overwritten

Synthetic task: a 16-line variable-tracking program in which the queried variable is overwritten k times; the control queries a variable assigned once in the same trace. After the trace is shuffled line by line, once-assigned variables are unaffected, accuracy on overwritten variables falls to chance as k grows, and in 93–99% of cases the model picks the value presented last. The tendency holds up to 64 overwrites (93–99%).

Relation to prior work: LCA (2605.26795) and 2605.07307 report that shuffling does not hurt, while 2605.22870 reports collapse on tracking. Whether states are overwritten explains both. 2605.22870 also reports collapse on logical deduction, which we do not observe (different setup: line-level shuffle of the model's own reasoning); the paper needs to address this.

Evidence 2 · Core

Explicit cues lose to position

Taking the last value is a sensible default when nothing else is known, so shuffling alone does not show an error. The decisive test is what the model does when explicit information contradicts position.

// Newest-first with a header (one k=4 item, illustrative). True history of e: 32 → 41 → 33 → 31 → 37 Let me trace the program. The steps below are listed from the most recent to the earliest. y = 42 n = 60 e = 37 ← newest (first e shown) e = 31 … e = 41 … e = 32 ← oldest (last e shown) Therefore, the final value of e is Qwen3-4B in this condition: 72% answer 32, 0% answer 37

The synthetic counterpart (Exp 2): when a wrong value comes last and is followed by “Hmm, that's wrong.”, most models reach only 0.5–10% in the conflict case; the best, Qwen3-14B, reaches 47.5%.

Evidence 3

Real reasoning text: support first, position breaks ties

In R1 reasoning traces from OpenR1-Math, we take the last paragraph that states the correct answer and copy it with the answer replaced by a nearby wrong number X. Both conclusions appear once, in either order, and derivation paragraphs are progressively removed to measure how much the later position decides the answer.

In complete natural traces, a single edit does not move the answer

In real traces the correct answer is usually checked and restated many times. None of these edits changes the reader's answer much, consistent with support coming first:

This matters for LLM graders, but answer recognition is a confound and a symmetric design is still needed.

Scope

The model's own reasoning versus other text it reads

The failures above occur when text is not presented in chronological order, or when two conclusions have equal support. A model's own reasoning is almost always chronological, so we tested separately how common and how costly position-answer mismatches are in unedited reasoning.

Qwen3-4B re-reading its own reasoning (BBH, answer sentence removed, no other edits)

Mismatches between position and answer are common in a model's own reasoning, but explicit judgments (“(B) is correct”) usually resolve them, at a cost of about 2 points. So the claim of this work is not that models misread their own reasoning. It is that when a model reads state updates that are not in chronological order and lack explicit judgments, it takes the value by position.

Such text is common in deployed systems: agent memory retrieval returns old and new facts ordered by relevance, distinguishable only by timestamps; git logs, email threads and changelogs list the newest entry first; tool outputs, conversation history and other models' reasoning are concatenated, as in CoT monitoring; and long reasoning revises the same quantity many times. The next experiments move to these settings.

Evidence 4

Across tasks: all 27 BBH tasks

On all 27 BBH tasks we shuffled Qwen3-4B's own reasoning line by line (3 seeds per item). We count only items the model answers correctly when re-reading in the original order and measure how many break after shuffling. The task categories were written into the code before the experiment ran.

Tasks that require tracking updated state break 39% of the time on average (object tracking 57–73%, multi-step arithmetic 42%, navigation 21%); partly related tasks 10%; the rest 4% (highest: web of lies 9%; logical deduction 1–10%).

Object counting and boolean expressions were labeled state-tracking in advance but break rarely (6% and 5%): the model's reasoning lists items (“I have 1 apple.”) and evaluates sub-expressions one at a time, never overwriting a quantity. What matters is whether the reasoning text actually overwrites state, not the task type.

Evidence 5

Mechanism: attention heads that read stated values

On the synthetic task we scored every Qwen3-4B attention head by its attention to the queried variable's values times its preference for the last-presented line. The top heads sit in layers 18–29 (for example, L29H11 puts 81% of its value attention on the last line). Zeroing them:

These heads are how the model reads stated values and conclusions, and the reading itself carries the positional bias; with them removed the model does not fall back on the derivation.

Risks

Main risks and unknowns

  • Biggest risk
    The effect weakens with scaleQwen3-14B handles well-structured step numbers and OLMo-2-13B does not, which points to training data or model family rather than scale alone. If 32B and 70B models handle the hard conditions, the claim narrows to small and mid-sized readers.
  • Key
    Reproduction in natural settingsThe conflicts so far are constructed under control. Reading its own reasoning costs the model little (about 2 points); the effect has to be shown in natural non-chronological settings such as agent memory retrieval and newest-first logs.
  • Medium
    Models of 7B and above run in 4-bitKey results need replication in bf16.
  • Medium
    Only reading is measuredThe model reads finished text; whether it reuses retracted values while generating has not been measured.
  • Medium
    Logical deduction on BBH disagrees with 2605.22870Shuffle granularity and models must be aligned before comparing.
  • To do
    LiteratureTest of Time (temporal reasoning, fact order), 2510.22752 (temporal biases in in-context retrieval) and memory benchmarks such as LongMemEval need a close read and a clear distinction.
Next steps

Plan and decisions to discuss

1. Natural non-chronological settings (feasible on the RTX 5080):

  • Agent memory retrieval: on a long-term memory benchmark with knowledge updates, compare retrieved results ordered by relevance (with timestamps) against the same results ordered by time. If relevance order is clearly worse, re-sorting by time is a free fix.
  • Newest-first logs: build “what is the current value” questions from real commit histories and changelogs, presented oldest-first and newest-first.
  • The model's own long reasoning: measure how often thinking-mode traces revise the same quantity, and whether later steps reuse retracted values.

2. Rent a GPU to test scale: one 80GB card (A800 / H800 / H100), about 30–50 hours. First run Exps 18, 19, 13 and 2 on 32B models (Qwen3-32B, OLMo-2-32B), about 10–15 hours, then decide on 70B. Also activation patching, bf16 replication of key results, and the generation-side experiments.

  1. Framing: the paper is about language models reading state updates by presentation position, with controlled experiments establishing the phenomenon and mechanism, and memory retrieval and logs showing the impact. Agreed?
  2. Compute: whether to rent a GPU, the budget, and whether the lab has cloud credits.
  3. Which natural setting first: agent memory retrieval, newest-first logs, CoT monitoring, or the model's own long reasoning.
  4. Target venue and timeline.
