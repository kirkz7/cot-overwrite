# 教训重读后全量重测

沿用上轮有可观察写入的 feedback 笔记定义。纳入全部后续跨会话成功整读，以同一笔记在同一会话第一次返回全文为起点，直到轨迹结束。单独报告实际读取次数和笔记×会话数。以 tool_call_id 配对，找不到结果时间的记录单列。

第一层全量统计读后用户发言、pushback 和成功返回的 Write/Edit/MultiEdit，以及读后用户发言之后同一笔记的重新写入。重新写入仅是可定位的轨迹信号，不能排除其他形式的纠正，也不能证明再犯。第二层需要核对教训适用性、已执行动作和用户反馈是否指向同一行为。延用至少 8 条明确适用、3 个仓库确认再纠正的推进线。未完成语义核对的案例保持未知，不用标签或模型补齐。

## 全量轨迹结果

54 条笔记、22 个仓库、52 个会话，共 67 个笔记×会话组合，对应 67 个独立读取调用，全部找到有时间戳的返回。一个调用对应多条返回记录，取最早返回作为起点。60/67 有后续用户发言，49/67（18 个仓库）出现 correction、failure_report 或 rejection 标签，59/67 有未被现有错误过滤规则排除的非记忆文件写入或编辑返回。4/67（3 个仓库）在用户发言后又修改了同一条教训。

先前单次调试将 non_pushback 一并计入，最终按三个正类重算。轨迹覆盖已查完，语义标签没有完成，67 条的适用性与复发状态均未核定。4 条同笔记改写是复核入口，预设推进线不能用它们直接判定。
