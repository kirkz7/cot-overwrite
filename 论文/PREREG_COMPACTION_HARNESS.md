# 横向比较各 harness 的压缩：保留了多少用户原话，压缩后用户是否更常纠正

2026-11-13 运行前锁定，接 `PREREG_COMPACTION_REAL.md`（Claude Code 负结果）。用户要求横向比较所有 harness。数据为 SWE-chat 本地全量。不调用 API 或模型，对外只报聚合数和转述。

## 看数据结构时已知的事实（只看了格式，没算任何结果）

SWE-chat 里有压缩记录的 harness，各自压缩后留在上下文里的东西不同：

| harness | 压缩记录 | 压缩后上下文 |
|---|---|---|
| Claude Code | 用户行 "This session is being continued…" | 模型写的九节摘要，其中一节逐条列用户发言 |
| Codex | `compacted` 元数据 | `replacement_history`：原样保留的用户消息（部分还有助手消息），加一个内容不可读的 compaction 项 |
| Pi、Oh My Pi | `pi:compaction` | 模型写的结构化摘要（Goal、Constraints & Preferences、Progress 等），加 `firstKeptEntryId` 之后原样保留的近期条目 |
| OpenCode | `opencode:compaction` | 紧随其后的一条助手回复，是模型写的 "## Goal…" 摘要 |
| Copilot CLI | `session.compaction_complete` | `summaryContent`，XML 分节的模型摘要 |
| Kimi Code | `context.apply_compaction` | 模型摘要（只有 2 次，单列不分析） |

Cursor、Gemini CLI 等没有压缩记录，不纳入。我上一轮说"Codex 的摘要不逐条列用户发言"是错的：Codex 是机械地原样保留用户消息。

分组（按结构预先定下）：
- 原话保留型：Claude Code、Codex。
- 自由摘要型：Pi、Oh My Pi、OpenCode、Copilot CLI。

## 量一：用户原话保留率（全量，确定性）

每个会话只取第一次压缩。压缩前每条有标签、长度至少 20 字符、不以 "<" 开头的用户发言，去掉空白后取前 60 个字符。若在压缩后上下文中原样出现，记为保留。
- Pi：在摘要中出现，或位于 `firstKeptEntryId` 对应条目之后，都记为保留。若无法把该 id 对上数据行，只看摘要，并报告对不上的数量。
- OpenCode：压缩行之后 5 行内第一条助手回复作为摘要。

报告每个 harness 的保留率，以及按会话重抽的 bootstrap 区间。这个指标只认原样出现，会低估转述保留，所以自由摘要型一定偏低。它只用来刻画设计差异，不当作"丢了"的证据。

预测：Codex 约 90%，Claude Code 约 80%，自由摘要型低于 15%。

## 量二：压缩前后的纠正比例（全量，确定性）

口径同 `PREREG_COMPACTION_REAL.md` 第一部分：
- 窗口 3，前后各至少 3 条有标签用户发言。
- 对每个 harness 报告后减前的差，以及对照 A（同会话安慰剂边界）。
- 主对比：自由摘要型合并后的差，减去原话保留型合并后的差。区间用按仓库重抽的 bootstrap，2000 次，种子 0。

判定线：主对比至少 +5 个百分点，且区间不含 0，才记为"压缩设计与压缩后纠正变多有关"。

预测：主对比约 +3 个百分点，未达线。自由摘要型样本少，区间会很宽。

## 量三：纠正是否指向压缩前说过的话（抽样，盲标）

R 的规则沿用上一轮揭盲前定下的收紧口径：只有用户提醒智能体"早先说过、且不是紧邻上一条的要求、约束、偏好或事实被当前行为违背或忽略"，才算 R=是；"还是没修好"记为否。

抽样（种子 0，每个仓库每组最多 2 条）：
- 自由摘要型：压缩后组最多 80 条，压缩前组最多 40 条。
- Codex：压缩后组 60 条，压缩前组 30 条。
- Claude Code 沿用上一轮的 120 条标注，不重标。

新条目全部混在一起打乱，用中性编号，隐藏组别和 harness，标完再揭盲。压缩后组 R=是 时，再标所指原话在压缩后上下文里：在 / 不在 / 走样。

判定线：自由摘要型压缩后 R=是 至少 10%，且比 Claude Code 压缩后（3.4%）和它自己的压缩前组都高至少 7 个百分点，才记为"自由摘要型有用户可见的压缩遗忘"。Codex 单独报告，不设线。

预测：自由摘要型压缩后约 8%，未达线。

## 限制

- 各 harness 的用户群、任务类型不同，比较的是 harness 加用户群，不能归因到摘要设计本身。
- 小 harness 样本少。
- 纠正标签很宽。
- 由一人标注。
