# 空白 1：真实会话里压缩之后，用户纠正是否变多、纠正是否指向压缩前说过的话

2026-11-13 运行前锁定。数据是 SWE-chat 本地全量（`D:\hf_cache\manual\swe-chat\conversations.parquet`），只看 Claude Code 会话。不调用 API 或模型，不用本地小模型筛选。对外只报告聚合数和转述，不引用原文（数据里有用户名、主机名和密码）。

背景（看数据结构时发现，未看任何结果）：Claude Code 的压缩摘要固定有九节，2933 份摘要里约 2766 份含"6. All user messages"一节，会把用户发言逐条列入摘要。所以在 Claude Code 上，"约束没进摘要"可能比 Compaction-Friendly 报告的少，"进了摘要但没遵守"可能更多。第二部分会把两者分开。

## 定义

- 压缩点：会话里第一条以 "This session is being continued from a previous conversation" 开头的用户行。
- 有标签的用户发言：role=user、turn_type=user_prompt、prompt_pushback 不为空、不是摘要行。按 turn_number、content_block_index 排序。
- 纠正：prompt_pushback 为 correction、failure_report 或 rejection。标签是数据集作者给的，我们不重标。

## 第一部分：全量，确定性统计

纳入全部合格会话：压缩点之前至少 3 条有标签的用户发言，压缩点到下一次压缩之间至少 3 条。每个会话取压缩前最后 3 条和压缩后最初 3 条，算纠正比例，主要量是压缩后减压缩前的配对差，取会话均值。置信区间用按仓库整体重抽的 bootstrap（2000 次，种子 0）。

两个对照：
- A，同会话的安慰剂边界：压缩前至少 6 条的会话，比较压缩前倒数第 6 到第 4 条和倒数第 3 到第 1 条。它估计会话越往后、纠正自然增加多少。
- B，没有压缩的 Claude Code 会话：至少 6 条有标签用户发言。每个会话的假边界从压缩会话的边界位置（压缩前有标签发言数）中抽，要求前后都留得下 3 条，种子 0。

判定线：主要差值至少 +5 个百分点，bootstrap 区间不含 0，并且比对照 A、B 的差值都至少高 3 个百分点，才记为"压缩后纠正变多"。否则记为"没有看到压缩后纠正变多"。敏感性分析：窗口 1 条和 5 条；手动 /compact 与自动压缩分开（压缩行之前 3 行内有 /compact 命令记为手动）。全部报告，不按结果挑。

预测：主要差值约 +3 个百分点，加上对照后达不到判定线。把握不大。

## 第二部分：抽样，人工标注纠正指向什么

两组：压缩后组取第一部分合格会话里压缩后最初 3 条中的纠正；压缩前组取压缩前最后 3 条中的纠正。每组随机抽 60 条（种子 0，每个仓库每组最多 2 条）。人工标注受时间限制只能抽样，这一部分的结论只适用于样本，置信区间照实报告。

每条标：
- R：这条纠正是否在重申或援引用户在更早、且不是紧邻上一条的发言里说过的要求、约束、偏好或事实。取值 是 / 否 / 看不出。两组用同一规则。
- 压缩后组 R=是 时，再标那条早先的话在压缩摘要里是否在：在 / 不在 / 被改写走样。

判定线：压缩后组 R=是 的比例至少 15%，且比压缩前组高至少 10 个百分点，才记为"用户可见的压缩遗忘"。压缩后 R=是 的条目里，"不在"加"走样"过半记为"主要是摘要丢了"，否则记为"主要是摘要在、行为没跟上"。看不出的单列，不计入分母也不补标。

预测：压缩后 R=是 约 20%，压缩前约 10%，差值刚到线附近；R=是 的条目里"摘要在"过半，因为有逐条列用户发言那一节。

## 限制

这是观察性数据，只能说相关。压缩发生在长会话后段，任务阶段本身会混淆，两个对照只能部分处理。prompt_pushback 是数据集作者用模型打的标签，未核验。第二部分 R 由我一人标注，没有第二标注者。

## 结果（2026-11-13，运行后补写）

### 第一部分

合格会话 716 个，来自 207 个仓库。纠正比例：压缩前最后 3 条为 54.6%，压缩后最初 3 条为 52.7%。

| 比较 | 会话数 | 后减前 | 95% 区间 |
|---|---|---|---|
| 主要（窗口 3） | 716 | −1.8 个百分点 | [−4.7, +1.0] |
| 对照 A，同会话安慰剂边界 | 599 | +1.9 | [−1.5, +5.6] |
| 对照 B，无压缩会话 | 3704 | +2.2 | [+0.9, +3.3] |
| 窗口 1 | 1119 | −1.6 | [−6.3, +2.3] |
| 窗口 5 | 496 | −1.5 | [−4.2, +0.9] |

结论：没有看到压缩后纠正变多，方向反而略负，未达判定线。预测的 +3 个百分点是错的。

- 手动 /compact 只有 4 个会话，其余都是自动压缩，无法分开比较。
- 纠正标签的基础比例约 54%，说明数据集的 correction 标签很宽：大多数是新指令或改需求，不只是在纠错。这会稀释任何效应。

### 第二部分

实际合格：压缩后组 1133 条，压缩前组 1172 条。每组抽 60 条，压缩后组来自 46 个仓库，压缩前组来自 50 个。

标注是盲的：两组打乱后用中性编号，不显示组别，全部标完再揭盲。

R 的口径在标注中做了收紧，两组用同一规则，在揭盲之前定下：
- 只有用户提醒智能体"早先说过的要求、约束、偏好或事实被当前行为违背或忽略"，才算 R=是。
- "还是没修好"类的报告记为否。那是没修好，不是遗忘。

| 组 | 是 | 否 | 看不出 | R=是 比例 |
|---|---|---|---|---|
| 压缩后 | 2 | 57 | 1 | 3.4% |
| 压缩前 | 0 | 58 | 2 | 0% |

未达判定线（需要至少 15% 且高 10 个百分点）。预测的压缩后 20% 是错的。

压缩后两条 R=是 的例子：
- 一条是智能体违背了用户四条之前说过的设计事实。
- 另一条是智能体新加了一个类，违背了用户早先"复用现有服务"的偏好。
- 两条所指的原话都在压缩前，都逐字出现在压缩摘要的"All user messages"一节里。
- 所以两条都属于"摘要在、行为没跟上"。只有 2 例，不能下结论。

### 解释与限制

在 Claude Code 上，用户可见的纠正几乎从不指向压缩前说过的话。一个可能的原因是 Claude Code 的摘要逐条保留用户发言。这是解释，没有检验。

这个结果不说明压缩不丢东西：
- 用户没发现的违反看不到。
- 纠正标签很宽。
- 第二部分只有一人标注、120 条样本。

后续可行性（只计数据量）：
- Codex 有 579 个压缩会话，278 个前后各有至少 3 条有标签发言。
- Pi 107 个（43 个合格），OpenCode 71 个（18 个合格）。

Codex 的压缩摘要不逐条列用户发言。同一检验在 Codex 上做，可以把"摘要设计"当变量来比，需要另写预注册。
