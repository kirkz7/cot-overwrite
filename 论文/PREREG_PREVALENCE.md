# 预注册：真实智能体记忆里，依赖更新有多常见（第 0 步，不花钱的小试）

写于 2026-11-11，**在读任何笔记正文之前**。此前只看过数据集说明和不含正文的统计。

## 问题
选题"依赖更新"面大不大。这一步只回答一小块：在真实的编程智能体记忆笔记里，"一条记下的事实变了，另一条取决于它的内容没跟着变"这种事出现得多不多。

## 数据
`EunsuKim/swe-chat-memory-stores`（社区数据集，ODC-BY，从 SWE-chat 的 Claude Code 会话里还原的记忆笔记）。已知的不含正文的统计：53 个仓库，266 条笔记，452 个不同状态，578 次观察；67 条笔记有两个以上版本，共 186 次版本变化，分布在 32 个仓库；观察最多的 3 个仓库占全部观察的 53%；时间 2026-02-10 到 04-19；笔记文件名以 `feedback_`（125）、`project_`（63）、`MEMORY.md`（52）为主。

## 怎么数

### A. 版本变化（186 次，全部看；每次看前后两版的差异）
每次变化归一个主类：
- **新增**：只加了新内容，原有陈述的意思没变。
- **改值**：原有某条陈述的值被替换、更正，或被标成过时。
- **进度**：任务状态往前走（完成了什么、计数、日期）。算一种易变状态的改值，单列。
- **删除**：删掉内容，没有替换。
- **改写**：重排、改措辞，事实没变。

对"改值"和"进度"两类再判一项：**同一个仓库的记忆里**（同一条笔记的前后版本，以及我读到的该仓库其他笔记），有没有别的陈述取决于被改的那个值（它的内容是由那个值推出来的，或者明说以它为条件）。
- 没有。
- 有，且这次一起改了（**已传播**）。
- 有，这次没改（**下游留旧**）。这就是我们说的依赖更新事件。
- 看不出来。

### B. 笔记抽样（按仓库分层随机抽 60 条的最终版本，种子 0）
这条笔记里有没有至少一处明说的依赖（"因为用了 X 所以 Y""如果 X 就 Y""取决于 X"这类）。有 / 没有。

## 我的预测
- P1 版本变化里"新增"≥ 50%；"改值"加"进度"合计 20–40%。
- P2 "改值"和"进度"里，存在下游依赖的 ≤ 25%；"下游留旧"占全部版本变化的 ≤ 10%。
- P3 抽样笔记里含明说依赖的占 20–50%。

## 判定线（只对这份数据）
把"已传播"和"下游留旧"合称依赖事件。
- **常见**：依赖事件 ≥ 全部版本变化的 10%，并且出现在 ≥ 25% 的有版本变化的仓库里（32 个里 ≥ 8 个）。
- **罕见**：< 3% 的版本变化，并且 < 10% 的仓库（≤ 3 个）。
- 其余写"介于两者之间"，不下结论。
同时报去掉观察最多的 3 个仓库之后的数。

## 已知限制（事先写下）
- 标注者只有我一个（模型）。标完后把每条的标签和依据写进表里，由用户抽查 30 条；抽查前的数只算初步。
- 观察是稀疏的：笔记只在被会话读写时才留下痕迹，两次观察之间发生了什么不知道。所以"这次没改"不等于"之后一直没改"，"下游留旧"是下限也可能是高估（下一次会话可能就改了）。
- 只看得到记忆笔记，看不到自动载入的指令文件和压缩摘要。
- 53 个仓库都是主动装了记录工具的早期用户，3 个仓库占一半以上观察。
- 这是 Claude Code 自己的笔记（反馈和偏好为主），不是聊天助理的用户记忆。结论不能搬到别的场景。
- 这一步量的是"笔记里的依赖更新"，不是"智能体因此出错"。后者要用 SWE-chat 全量会话，另行预注册。
- 数据集说明提到笔记里有用户名、主机地址、一处明文密码和未发表的研究内容。报告只给汇总数和改写过的例子，不引原文里的这类信息。

# 第 1 步预注册：派生内容过时（索引行对笔记）

写于 2026-11-12，在逐条判断之前。方向已改为只做智能体的记忆（用户，导师会后）。

## 为什么量这个
Claude Code 的记忆有一个天然的"派生"结构：`MEMORY.md` 是索引，每一行是对一条笔记的一句描述。笔记更新了、索引那一行没跟着改，就是派生内容过时。Concord 把"由过时观察派生出来的摘要、计划、决定"明确留作以后的工作；第 0 步确认的三例"下游留旧"里有一例正是这种形态。这一步在手头的 53 个仓库数据上数一遍，看值不值得在 SWE-chat 全量上做。

## 已知的不含判断的数（机械提取）
`MEMORY.md` 观察 190 次，其中形如"- [标题](文件.md) — 描述"的索引行 1546 行。被链接的笔记在该次索引观察之前（含同时）被观察到过的有 1187 行，分布在 20 个记忆库（20 个仓库）。去重后是 **236 个不同的（笔记、索引行文字、笔记当时的描述字段）组合，涉及 154 条笔记**。索引行和笔记自带的 `description` 字段字面相同的只有 14 行，所以不能靠字面比较，要逐条读。

## 怎么判
单位：上面 236 个组合里的每一个。给判断者看：索引行；该笔记在索引被观察到的那一刻之前最后一次被观察到的内容（名称、描述、开头若干行）。
- **一致**：索引行和笔记当时的内容不矛盾（概括得粗、少了细节都算一致）。
- **过时**：索引行里有一处具体说法（状态、数字、结论、下一步）和笔记当时的内容矛盾，而且笔记的说法更新。
- **反向**：索引行比笔记新（笔记落后）。单列。
- **看不出**：笔记内容被截断或信息不够。

## 预测（我已经在第 0 步读过一部分索引行的差异，包括两例留旧，所以这些预测不是盲的）
- P1 过时的组合占 5–15%。
- P2 过时集中在 `project_` 类笔记（带进度的），`feedback_` 类 ≤ 3%。
- P3 至少 5 个记忆库里出现过时。

## 判定线
- **派生内容过时常见**：过时 ≥ 10% 的组合，并且出现在 ≥ 25% 的记忆库（20 个里 ≥ 5 个）。
- **罕见**：< 3% 并且 ≤ 2 个记忆库。
- 其余写"介于两者之间"。

## 限制（事先写下）
- 单个标注者（模型）；标完后给用户一份抽查表。
- 索引是每次会话开始时自动载入的，但数据里只有它被工具读写的那些时刻；笔记在两次观察之间可能改过。所以"过时"是按"最后一次看到的笔记内容"判的，可能高估也可能低估。
- 20 个记忆库，早期用户；去重是按文字去的，同一条过时的索引行被读到多次只算一次，所以这不是"智能体读到过时索引的频率"。
- 这一步只数有多常见，不看它有没有造成后果。

# 第 1 步在 SWE-chat 全量上重做（预注册，写于 2026-11-12，逐条判断之前）

用户要求在全量上重做。只看过下面这些不含判断的计数，没有读任何一组配对的内容。

## 数据和还原
程序 `论文/swechat_memory.py`。从 `conversations` 表抽出所有落在 Claude Code 记忆目录的读、写、编辑（6383 次调用），按时间还原每条笔记的完整状态：完整读取和写入直接给出全文；编辑在已知全文上应用；没有已知全文的编辑丢弃（342 次），旧片段对不上的丢弃（45 次）。得到 5291 个已知状态、1860 条笔记、295 个记忆库、233 个仓库。和快照数据相比，多出来的主要是编辑还原出的状态（2082 个）。

配对规则和第 1 步相同：每个已知的 `MEMORY.md` 状态里的每一行"- [标题](文件.md) — 描述"，配上该笔记在那一刻之前最后一个已知状态；按（记忆库、笔记、索引行文字、笔记描述字段）去重。结果 **1762 组**，182 个记忆库、149 个仓库；最大的一个记忆库 375 组。按笔记类型：无前缀的 779、`project_` 480、`feedback_` 379、`reference_` 86、其他 38。

- 判断规则、四个标签（一致 / 过时 / 反向 / 看不出）和第 1 步完全相同。看的内容：索引行；笔记的描述字段；笔记正文开头。
- 报告：样本里各标签的比例（带按记忆库聚类自助法的 95% 区间）；有过时的记忆库占样本中记忆库的比例；按笔记类型分开报。

## 预测（看过快照数据的结果，不是盲的）
- Q1 过时占 1–4%。
- Q2 `feedback_` 类过时 ≤ 1%；过时集中在 `project_` 和无前缀的笔记。
- Q3 反向（索引比看到的笔记新）比快照数据少，因为编辑被还原了，"看到的笔记"更接近真实最新版。

## 判定线（沿用第 1 步，记忆库一条换成比例）
- **常见**：过时 ≥ 10%，并且出现在 ≥ 25% 的样本记忆库。
- **罕见**：过时 < 3%，并且出现在 ≤ 10% 的样本记忆库。
- 其余写"介于两者之间"。
