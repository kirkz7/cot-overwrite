问题地图：记忆里的信息变了之后

2026-11-09 整理，供周三讨论。依据是本轮读过的约 20 篇论文；每篇只读了检索工具返回的相关页，没有通读。带 † 的只看过摘要或别人论文里的描述。"空白"只在这个范围内成立。

大问题：对话历史很长，里面的信息会变。回答时怎样保证用的是"现在仍然有效"的那个状态？
已有人做 做了但没解决 空白 我们手里已有的

图一：问题有哪几种

  • A. 同一件事直接改口 已有人做
    例：先说住奥斯汀，后来说搬到西雅图。
    基准：LongMemEval 知识更新题、MemoryAgentBench 冲突消解、MemConflict。强读者上已接近做完（RAW-RAG + GPT-4.1-mini 91–95）。
  • B. 没明说的更新 做了但没解决
    例：没说"不住西雅图了"，只说"在波特兰签了租约"。
    基准：STALE 第一类。最好的模型总分 55%。
  • C. 上游变了，下游要跟着变（依赖传播） 做了但没解决
    • 级联：有规则说明下游的新值，要算出来。MEME 级联题；StateMemBench 的"派生值没重算"。
    • 失效：没有规则给新值，旧值不能再信，应该答"不确定"。MEME 失效题。
    • 隐式传播：依赖关系没写出来，靠常识。STALE 第二类（腿骨折 → 骑车通勤不成立）；StateGraph、PACMI 的自建集。
    这是五个基准都在测的同一件事，区别只在依赖关系是写明的（MEME、StateMemBench）、标注给的（PACMI）还是要自己推的（STALE、StateGraph）。
  • D. 用户要求删除 做了但没解决
    MEME 删除题；AfterDeleteBench†、记忆遗忘基准†。弱读者上加一段说明就能从 39 升到 92。
  • E. 带限定条件的信息 空白 我们有先导数据
    例外（今天点了别的）、假设、角色扮演、别人的事。
    没有专门基准。我们的笔记本先导测试每类只有 8 题，信号弱；StateGraph、StateMemBench 各有少量"临时例外"用例。
  • F. 时间和顺序 已有人做 cot-overwrite
    事件时间 ≠ 到达顺序；证据的摆放顺序。
    Berkeley（按陈述时间排序即可恢复）、TSM†、TOKI†、Zep、RoutePrism；读者按位置读错是我们上一个项目。

图二：在哪一步解决

  • 一、写入时：每来一条消息，就整理一次记忆。
    • 改写、合并、删除旧记忆 做了但没解决
      Mem0、A-MEM、MemoryOS。RAW-RAG 实测 Mem0 的更新和删除只占 2.5–4.4%，关掉后分数更高。
    • 不删，只标状态（当前 / 过时 / 历史）已有人做
      Zep（有效期）、A-TMA†、CALM†、MINDSET†、PACMI（四种状态）。
    • 记录"谁依赖谁"，上游变了就把下游标成失效 已有人做
      CUPMem（预设槽位表 + LLM 裁决）、StateMem（状态单元 + 依赖边，传播不调 LLM）、StateGraph（用反事实提问验证依赖边）、PACMI（依赖边由标注给出）、MD-flat + Opus 4.7（让大模型自己写"如果…则…"并回填，成本约 70 倍）。
    • 训练写入策略 已有人做
      Supersede†、Memory-R1†。
    • 共同弱点：每条消息都要调 LLM；依赖关系要么预设、要么标注、要么靠 LLM 猜；各用自建小基准，没有一篇在 MEME 上报数。
  • 二、读取时：记忆只存原文，问题来了再处理。
    • 检索
      • 按相关度取，再重排 已有人做 RAW-RAG。
      • 缺什么补什么，多取几轮 已有人做 QEMem、BFR、MERA（训练了 0.6B 规划器）。只在 LoCoMo、LongMemEval 上测。
      • 按时间段定位 已有人做 TIDER（NeurIPS 2026，训练 1.7B 定位器）。
      • 顺着依赖去取：取到目标后，再取它依赖的规则和上游的最新状态 空白
    • 摆放：把取到的证据按时间排好 已有人做 cot-overwrite
      LongMemEval 官方代码、RAW-RAG（只在 MEME 上排）。我们量过不排的代价：4B、8B 掉 14–17 点。
    • 作答
      • 提示词：先列出每个值的变更链，再按规则裁决 已有人做 StateMem 的包装（6 个后端各涨 32–67 点）；RAW-RAG 的任务说明。
      • 提示词对级联 / 失效 做了但没解决 MEME 试过自动提示词优化，仍在地板。
      • 换更强的读者 做了但没解决 证据给全时 DeepSeek-V4-Flash 能到 82–92，GPT-4o-mini 只有 2–39。走真实检索时强读者也只有 4–29。
      • 训练读者学会重建状态 空白 有配方 我们的 E13–E19.2 只训练了"顺序 / 时间"这一种。
  • 三、答完再查：先出草稿，再对照状态审核、重写 已有人做
    StateAuditor（2608.01619）。STALE 上 68.6 → 73.6。它试过训练一个 4B 审核器，没有追上大模型。
  • 四、不做记忆，整段历史放进上下文 做了但没解决
    MEME 上 gpt-4.1-mini 级联 3%；DeepSeek-V4-Flash 48%。StateMemBench 上最好的长上下文模型 27.7%。

这些论文彼此重合在哪

  1. 同一个现象被发现了至少五次：证据取到了，模型仍按旧值答。STALE（新证据取到 77.5%，仍有 56–99% 答错）、StateMem（证据给全时 44% 的错是这类）、MEME（失效题 84% 的错是这类）、MemConflict、2610.36308，加上我们的 cot-overwrite。
  2. 依赖传播有五个基准，互不通用。MEME、STALE、StateMemBench、StateChangeBench（StateGraph）、PACMI 自建集。每家只在自己的基准上报主结果。
  3. 写入时"状态 + 依赖图"有四家，做法很像。CUPMem、StateMem、StateGraph、PACMI。其中 StateGraph 和 PACMI 是同一个第一作者。
  4. "相关不等于充分"有三家，同月发表。QEMem、BFR、MERA，都只测 LoCoMo 和 LongMemEval。
  5. 两派结论相反，没有人直接对比。MEME、STALE 说必须在写入时传播；RAW-RAG 说写入时改写没用，原文加强读者就够。RAW-RAG 自己写明："写入时构建状态是否帮助弱读者，仍是开放问题。"

还没人讨论的（按我认为的价值排序）

  1. 空白 MEME 的级联和失效题，用便宜的配置做上去。现在唯一有效的配置贵 70 倍。
  2. 空白 读取时顺着依赖去取证据。三篇"证据充分"的检索方法都没在依赖题上测过，能不能直接用上是未知的。
    11-10 我们的小试验（MEME 探索集 30 集，Qwen3 检索模型，只量证据不量正确率）：前 15 个窗口里证据已齐的题，级联 75.5%、失效 67.5%、删除 100%；缺的全是触发事件；用上游实体再检索一次可以补到 100%。所以这一条更像方法里的一个小部件，主要缺口在第 3 条（读者）。详见 PREREG_MEME_PILOT.md。
  3. 空白 训练读者做状态重建。唯一一次训练尝试是审核器，失败了。这既是空位，也说明不容易。
  4. 空白 写入派和读取派放在同一个基准、同一个读者下比。特别是读者变弱时谁占优。
  5. 空白 带限定条件的信息（例外、假设、别人的事）。没有基准，我们的信号也弱，风险最大。

名词

级联题（MEME 原例）。用户先说："如果我的健康状况变了，锻炼就改成每周两次瑜伽。"很多轮之后说："肌腱炎治好了。"问：现在的锻炼安排是什么？正确答案是"每周两次瑜伽"。没有任何一句话直接说"我现在练瑜伽"，要把规则和变化合起来算。
失效题（MEME 原例）。部署平台从 Narvex Cloud 换成 Thandrel Infra。日志地址、镜像、部署命令原来都跟着旧平台，但没人说换平台后它们变成什么。问：现在的部署命令是什么？正确答案是"不确定，需要重新确认"，不能照报旧命令。
写入侧做依赖。消息进来时，系统除了存"B 的值是 X"，还存一条"B 依赖 A"。以后 A 变了，系统顺着这条线把 B 标成"失效"或"待确认"，回答时就不会把 B 的旧值当成现在的值。难点是"B 依赖 A"从哪来：CUPMem 用预设的槽位表，PACMI 靠人工标注，StateGraph 和 StateMem 让 LLM 在写入时判断。
读取时状态重建。写入时什么都不整理，只存原文。问题来了，先把相关原文取出来，再由读者（或一段提示词、或一个训练过的小模型）现场判断每个值现在还算不算数。
