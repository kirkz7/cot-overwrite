问题地图：依赖传播该在写入时做，还是读取时做

2026-11-10 重写（上一版 11-09）。这一版精读了 MEME、RAW-RAG、CUPMem、StateMem、StateGraph、PACMI 六篇的正文、附录和能找到的代码；其余论文仍只读过相关页，带 † 的只看过摘要或别人的转述。我们自己的数都来自 MEME 探索集 30 集、本机 Qwen3-8B 读者、本机 14B 判分（不是官方的 gpt-4o），只能当探索用。

问题：上游信息变了，下游的值要跟着变（或者不能再信）。这一步该由写入时的系统做、读取时的读者做，还是两边一起做？对弱读者，写入到底帮不帮得上？
已有人做，有数 做了但没解决 空白 我们量过 现在做不了

先说结论：和上一版相比，认识变了的五点

  1. "写入派对读取派没人直接比"这句话是错的。RAW-RAG 表 4 已经把 7 个通用写入系统和自己放在 MEME 上、同一个读者下比了，两个读者都测了：全部级联 ≤ 9、失效 ≤ 20，没有交叉点。空白缩小为"依赖感知的写入系统"。
  2. 四家依赖感知的写入系统都没上过 MEME，但只有一家有公开代码。见下面"现在能不能做"一节。
  3. 检索不是主要缺口。我们量的：前 15 个窗口里证据已齐的题，级联 75.5%、失效 67.5%、删除 100%；用上游实体再检索一次补到 100%。把缺的证据补给读者，正确率没有变化。
  4. 读者是主要缺口，提示词只能解决一部分。在 8B 读者上：删除题靠提示词能到 47–67；级联题最好到 31–35；失效题所有提示词都 ≤ 10，连告知题型也只有 10。
  5. 写入有没有用，取决于写入者多强、写下来的是什么。同一个文件式系统，写入模型换成 Opus 才从 0 升到 32。把正确答案直接写给读者，小读者级联 74、失效仍只有 37。

图一：问题有哪几种（现在只做 C 和 D）

  • A. 同一件事直接改口 已有人做 强读者上接近做完（RAW-RAG + GPT-4.1-mini 91–95）。
  • B. 没明说的更新 做了但没解决 STALE 第一类，最好的模型总分 55%。
  • C. 上游变了，下游要跟着变 做了但没解决 ← 现在的题
    • 级联：有规则给出下游的新值，要算出来。MEME 级联题、StateMemBench。
    • 失效：没有规则给新值，旧值不能再信，应答"不确定"。MEME 失效题。
    • 隐式传播：依赖关系没写出来，靠常识。STALE 第二类、StateGraph 和 PACMI 的自建集。先不做。
  • D. 用户要求删除 做了但没解决 我们量过 加一段说明就能解决大半：8B 上 7 → 47（依赖规则）/ 67（状态追踪包装）/ 80（告知题型）。当作"不伤害"检查带着，不是主战场。
  • E. 带限定条件的信息 空白 例外、假设、别人的事。没有基准，先搁置。
  • F. 时间和顺序 已有人做 上一个项目 cot-overwrite。

图二：一道依赖题要过四关，分数丢在哪一关

  • 第 1 关 写入：消息进来时要不要整理。
    • 不整理，只存原文（读取派）。RAW-RAG。信息不丢，全部压力在读者。
    • 通用整理（抽事实、合并、建图）做了但没解决
      Mem0、图谱类等 7 个系统。RAW-RAG 把它们的整个记忆库都给读者，改写过的库比原文证据低 8–30 点：写入时就把触发事件或规则丢了。
    • 记依赖，上游变了给下游打标记 已有人做，没上过 MEME
      CUPMem、StateMem、StateGraph、PACMI。写下来的是"这个值需复查"，新值仍要读者自己算。
    • 写入时直接把新值算出来 只有 Opus 做到
      MEME 表 4：文件式系统 + Opus 4.7 当写入者，级联 0 → 32、失效 7 → 59。代价：成本约 70 倍，精确回忆 95 → 60，追踪 80 → 20。
  • 第 2 关 检索 我们量过：不是主要缺口
    缺的全是触发事件（"肌腱炎好了"这类话和问题不像）。用上游实体再检索一次即可补齐。是方法里的小部件。
  • 第 3 关 摆放 已有人做 按时间排。LongMemEval 官方代码、RAW-RAG、我们的上一个项目。
  • 第 4 关 读者作答 主要缺口 我们量过
    • 官方提示词：8B 级联 0、失效 0。答对前置题的读者，变更后没有一题从旧值改答新值。
    • 打开思考：级联 35、失效 5。
    • 已发表的提示词：StateMem 的状态追踪包装级联 31、失效 5（比配对对照高 27 点，但 119 题里 38 题没答完，精确回忆 100 → 72）；RAW-RAG 的依赖规则级联 2、失效 0；告知题型级联 18、失效 10。
    • 换强读者：证据给全时 DeepSeek-V4-Flash 级联 82；走真实检索时仍 ≤ 9。
    • 训练读者 空白 唯一一次训练尝试是 StateAuditor 的 4B 审核器，没追上大模型。

这些论文彼此重合在哪

  1. 同一个现象被发现了至少五次：证据取到了，模型仍按旧值答。STALE、StateMem、MEME、MemConflict、2610.36308，加上我们的 cot-overwrite 和这次的 8B 试验。
  2. 依赖传播有五个基准，互不通用。MEME、STALE、StateMemBench、StateChangeBench、PACMI 自建集。每家只在自己的基准上报主结果。
  3. 写入时"状态 + 依赖图"有四家，做法很像，写下来的都是标记而不是算好的值。StateGraph 和 PACMI 是同一个第一作者。
  4. 写入派自己的数据也不支持"写入帮弱读者"。StateMem 在自己的基准上、Qwen-9B：写入系统 0.283，读取时的提示词包装 ≥ 0.567。但它的写入者也是 9B，是"弱写入 + 弱读者"。

名词

级联题（MEME 原例）。用户先说："如果我的健康状况变了，锻炼就改成每周两次瑜伽。"很多轮之后说："肌腱炎治好了。"问：现在的锻炼安排是什么？正确答案是"每周两次瑜伽"。没有任何一句话直接说"我现在练瑜伽"，要把规则和变化合起来算。
失效题（MEME 原例）。部署平台从 Narvex Cloud 换成 Thandrel Infra。部署命令原来跟着旧平台，没人说换平台后它变成什么。问：现在的部署命令是什么？正确答案是"不确定，需要重新确认"，不能照报旧命令。
真通过率。变更之后的题答对，而且同一题在变更之前也答对，才算通过。只看变更之后会把"碰巧一直答新值"的读者算进去。
写入产物的两种形态。"只打标记"：记忆里写"锻炼安排：〈旧的安排〉（需复查，因为健康状况变了）"，新值留给读者算。"值已算好"：记忆里直接写"当前锻炼安排：每周两次瑜伽"。前者是四家依赖感知系统的做法，后者只有 Opus 当写入者时出现过。
写入检查。不看最终答案，只看记忆里有没有出现该有的东西（新值或失效标记）。有而答错是读者的问题，没有就是写入的问题。
